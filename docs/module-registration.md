# 관리자 태양광 모듈 등록

관리자 로그인 후 `admin.html`의 **기술자료 관리 → 태양광 모듈 등록**에서
`/reg-module.html`을 엽니다. 화면 파일은 `private/reg-module.html`에 있으며
Express 인증 경로로만 제공합니다. `public`에 복사하지 마세요.
비로그인 요청은 관리자 로그인 화면으로 이동하고 API는 401을 반환합니다.
기존 관리자 로그인·CSRF 검증을 사용하며, 세션 쿠키 경로가 `/`로 변경되어
로그인 후 서버가 페이지 요청에서도 인증을 확인합니다. 서버 재시작 후 다시 로그인하세요.

## 서버 준비

기존 Node.js 24 / `npm ci` 설치에 더해 Poppler 실행 파일
`pdfinfo`, `pdftotext`, `pdftoppm`이 PATH에 필요합니다.
Tesseract와 OCR 언어 모델은 사용하지 않습니다.

Debian/Ubuntu 서버에서:

```sh
sudo apt-get update
sudo apt-get install -y poppler-utils
npm ci
npm start
```

PM2 등으로 서비스를 관리한다면 `npm start` 대신 해당 서비스를 재시작하세요.
PDF 미리보기는 `/usr/bin/pdftoppm`이 있으면 사용하고, 없으면 PATH의
`pdftoppm`을 사용합니다. `MODULE_PDFTOPPM_BIN`으로 별도 경로를 지정할 수 있습니다.

## 저장과 운영

등록 카탈로그와 원본 PDF는 기본적으로 `uploads/modules/`에 저장합니다.
환경변수 `MODULE_DATA_DIR`로 서버가 쓸 수 있는 영속 디렉터리를 지정할 수 있습니다.
이 디렉터리 전체를 영속 볼륨으로 유지하고 백업하세요. 정적 공개 경로가 아닙니다.
카탈로그는 원자적 파일 교체와 배타적 잠금으로 갱신합니다.
같은 호스트/공유 POSIX 파일시스템에 있는 프로세스가 동일 경로를 사용해야 합니다.
서로 다른 디스크를 사용하는 여러 서버에는 별도 DB 기반 저장소가 필요합니다.
원본 PDF에 개인정보가 포함되지 않았는지 확인한 뒤 업로드하세요.

PDF는 한 개당 20MB, 100페이지 이하입니다. 사양표가 있는 페이지를 선택하여
한 페이지씩 분석합니다. 텍스트가 포함된 PDF에서만 사양을 자동 추출합니다. 이미지뿐인 페이지는
안내 메시지와 미리보기를 표시하며, 관리자가 사양을 직접 입력할 수 있습니다.
페이지당 이미지 크기, 프로세스 시간, 출력 크기를 제한하며 동시 분석은 한 건입니다.
분석 도구는 최신 보안 업데이트를 적용하고 서버의 제한된 OS 계정으로 실행하세요.
업로드 유효기간은 1시간이며 세션 소유자만 사용할 수 있습니다.
서버 재시작으로 남은 미완료 파일은 `uploads/modules/imports/`에 있을 수 있습니다.
활성 업로드가 없는 점검 시간에 이 디렉터리의 오래된 PDF만 정리할 수 있습니다.
카탈로그와 등록된 PDF는 지우지 마세요.
프로세스 강제 종료 후 `.catalog.lock`이 남았다면 실행 중인 등록 작업이 없는 것을
확인한 운영자만 잠금 파일을 제거하고 다시 등록하세요.

## 등록 규칙

1. PDF를 업로드하고 사양표 페이지를 선택합니다.
2. 확실하게 읽을 수 있는 단일 값만 폼에 자동 입력합니다.
   다중 모델 표, 모호한 값, 읽지 못한 값은 원본과 추출 텍스트를 보며 직접 입력합니다.
   표 형식이 제조사마다 다르므로 모든 PDF를 완전 자동 해석하지 않습니다.
3. STC 전기 특성, 온도계수(%/℃), 퓨즈 정격과 효율을 입력합니다.
   양면 값은 기존 계산기의 **후면 일사 13.5% 기준**으로 입력합니다.
   단면 모듈은 STC 값을 사용하는 버튼을 선택합니다. 확인되지 않은 값을 추정하지 마세요.
4. 검토 완료를 선택하고 등록합니다. 새로 연/새로고침한 계산기에서 즉시 선택할 수 있습니다.
   계산 워커도 같은 카탈로그를 읽으므로 서버 재시작은 필요 없습니다.

제조사와 모델명은 NFKC 정규화, 대소문자·공백 차이를 무시해 비교합니다.
제조사+모델명이 같으면 시리즈나 사양이 달라도 HTTP 409로 등록을 거절하며,
기존 항목을 덮어쓰지 않습니다. 기본 카탈로그도 중복 검사에 포함됩니다.
기존 데이터의 실제 개수를 읽어 표시하며 시안의 예시 숫자를 고정하지 않습니다.
등록 후 수정·삭제·비활성화 기능은 포함하지 않습니다.

## 검증

```sh
node --test test/module-registration.test.js
node test/module-registration-ui.cjs
node --test --test-isolation=none test/calculator.test.js
node test/calculator-ui.cjs
```

등록 테스트는 OS 임시 디렉터리를 사용하므로 실제 카탈로그를 바꾸지 않습니다.
UI 검증에는 이미지에 제공된 Playwright와 Chromium이 필요합니다.
계산기 UI 테스트는 3000번 포트를 사용하므로 자신의 개발 서버를 먼저 중지하세요.
