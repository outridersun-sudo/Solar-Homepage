# 관리자 태양광 모듈 등록

관리자 로그인 후 `admin.html`의 **기술자료 관리 → 태양광 모듈 등록**에서
`/reg-module.html`을 엽니다. 화면 파일은 `private/reg-module.html`에 있으며
Express 인증 경로로만 제공합니다. `public`에 복사하지 마세요.
비로그인 요청은 관리자 로그인 화면으로 이동하고 API는 401을 반환합니다.
기존 관리자 로그인·CSRF 검증을 사용하며, 세션 쿠키 경로가 `/`로 변경되어
로그인 후 서버가 페이지 요청에서도 인증을 확인합니다. 서버 재시작 후 다시 로그인하세요.

## 서버 준비

기존 Node.js 24 / `npm ci` 설치에 더해 Poppler 실행 파일
`pdfinfo`, `pdftotext`, `pdftoppm`이 PATH에 필요합니다.
Tesseract와 OCR 언어 모델은 사용하지 않습니다.

Debian/Ubuntu 서버에서:

```sh
sudo apt-get update
sudo apt-get install -y poppler-utils
npm ci
npm start
```

PM2 등으로 서비스를 관리한다면 `npm start` 대신 해당 서비스를 재시작하세요.
PDF 미리보기는 `/usr/bin/pdftoppm`이 있으면 사용하고, 없으면 PATH의
`pdftoppm`을 사용합니다. `MODULE_PDFTOPPM_BIN`으로 별도 경로를 지정할 수 있습니다.

## 저장과 운영

등록 카탈로그와 원본 PDF는 기본적으로 `uploads/modules/`에 저장합니다.
환경변수 `MODULE_DATA_DIR`로 서버가 쓸 수 있는 영속 디렉터리를 지정할 수 있습니다.
이 디렉터리 전체를 영속 볼륨으로 유지하고 백업하세요. 정적 공개 경로가 아닙니다.
카탈로그는 원자적 파일 교체와 배타적 잠금으로 갱신합니다.
같은 호스트/공유 POSIX 파일시스템에 있는 프로세스가 동일 경로를 사용해야 합니다.
서로 다른 디스크를 사용하는 여러 서버에는 별도 DB 기반 저장소가 필요합니다.
원본 PDF에 개인정보가 포함되지 않았는지 확인한 뒤 업로드하세요.

PDF는 한 개당 20MB, 100페이지 이하입니다. 사양표가 있는 페이지를 선택하여
한 페이지씩 분석합니다. 텍스트가 포함된 PDF에서만 사양을 자동 추출합니다. 이미지뿐인 페이지는
안내 메시지와 미리보기를 표시하며, 관리자가 사양을 직접 입력할 수 있습니다.
페이지당 이미지 크기, 프로세스 시간, 출력 크기를 제한하며 동시 분석은 한 건입니다.
분석 도구는 최신 보안 업데이트를 적용하고 서버의 제한된 OS 계정으로 실행하세요.
업로드 유효기간은 1시간이며 세션 소유자만 사용할 수 있습니다.
서버 재시작으로 남은 미완료 파일은 `uploads/modules/imports/`에 있을 수 있습니다.
활성 업로드가 없는 점검 시간에 이 디렉터리의 오래된 PDF만 정리할 수 있습니다.
카탈로그와 등록된 PDF는 지우지 마세요.
프로세스 강제 종료 후 `.catalog.lock`이 남았다면 실행 중인 등록 작업이 없는 것을
확인한 운영자만 잠금 파일을 제거하고 다시 등록하세요.

## 등록 규칙

1. PDF를 업로드하고 사양표 페이지를 선택합니다.
2. 확실하게 읽을 수 있는 단일 값만 폼에 자동 입력합니다.
   다중 모델 표, 모호한 값, 읽지 못한 값은 원본과 추출 텍스트를 보며 직접 입력합니다.
   표 형식이 제조사마다 다르므로 모든 PDF를 완전 자동 해석하지 않습니다.
3. STC 전기 특성, 온도계수(%/℃), 퓨즈 정격과 효율을 입력합니다.
   양면 값은 기존 계산기의 **후면 일사 13.5% 기준**으로 입력합니다.
   단면 모듈은 등록할 수 없습니다. 양면 제품 확인 페이지와 원본 근거를 필수로 입력합니다.
   STC·BNPI 값을 모두 입력해야 하며, 확인되지 않은 값을 추정하지 마세요.
4. 검토 완료를 선택하고 등록합니다. 새로 연/새로고침한 계산기에서 즉시 선택할 수 있습니다.
   계산 워커도 같은 카탈로그를 읽으므로 서버 재시작은 필요 없습니다.

제조사와 모델명은 NFKC 정규화, 대소문자·공백 차이를 무시해 비교합니다.
제조사+모델명이 같으면 시리즈나 사양이 달라도 HTTP 409로 등록을 거절하며,
기존 항목을 덮어쓰지 않습니다. 기본 카탈로그도 중복 검사에 포함됩니다.
기존 데이터의 실제 개수를 읽어 표시하며 시안의 예시 숫자를 고정하지 않습니다.
등록 후 수정·삭제·비활성화 기능은 포함하지 않습니다.

## 검증

```sh
node --test test/module-registration.test.js
node test/module-registration-ui.cjs
node --test --test-isolation=none test/calculator.test.js
node test/calculator-ui.cjs
```

등록 테스트는 OS 임시 디렉터리를 사용하므로 실제 카탈로그를 바꾸지 않습니다.
UI 검증에는 이미지에 제공된 Playwright와 Chromium이 필요합니다.
계산기 UI 테스트는 3000번 포트를 사용하므로 자신의 개발 서버를 먼저 중지하세요.

## 모델별 표 자동 추출 개선 (v2)

인식 가능한 표에서 여러 모델을 찾으면 먼저 ‘등록할 모델 선택’을 표시합니다.
모델 선택 전에는 모델별 전기값을 자동 입력하지 않습니다. 모델을 바꾸면 이전 모델의
입력값과 검토 체크를 초기화해 사양이 섞이지 않도록 합니다.

검증한 원본의 사양표는 모두 2페이지입니다.

| 사양서 | 모델 수 | 처리 |
| --- | --- | --- |
| LONGi LR7-72HVH 630~650M | 5 | STC 입력, NOCT 참고 표시 |
| Qcells Q.TRON XL-G2R.9 / BFG 635~640W | 2 | STC·BNPI 입력, NMOT 참고 표시 |
| Canadian Solar CS6.2-66TB 610~640H | 7 | STC 입력, NMOT·양면 증가율 참고 표시 |
| TW Solar TWMNF-66HD 730~750W | 5 | 좌측 STC·우측 BNPI 분리 입력 |

이는 위 사양서 형식을 지원하는 규칙 기반 추출입니다. 다른 시리즈·레이아웃에서는
보수적인 단일 값 추출 또는 직접 입력으로 전환됩니다. 제조사명 자동 분류와 모델명도
원본 라벨과 대조하세요. Qcells는 공통 제품군명에 정격 출력을 붙여 구분합니다.

BNPI가 없는 사양서에는 값을 만들어 채우지 않습니다. NOCT·NMOT를 BNPI로 옮기거나
후면 ‘발전 증가율’ 10%를 ‘일사량’ 13.5%와 같게 취급하지 마세요.
Canadian Solar와 같은 양면 제품은 해당 계산 기준의 추가 사양 확인이 필요합니다.
LONGi 사양서에 BNPI가 없으면 등록할 수 없습니다. 단면 제품도 등록 불가입니다.
TW 원본의 Isc 온도계수 -0.046은 부호를 유지하고 경고하며, 등록 후 기존 계산기의
보수적인 전류 보정을 사용합니다. 원본 부호는 제조사에 확인하세요.

검증 명령은 데이터 경로 환경변수가 섞이지 않게 각각 별도 프로세스로 실행하세요.

```sh
node --test --test-isolation=none test/module-pdf-parser.test.js
node --test --test-isolation=none test/module-registration.test.js
node test/module-model-ui.cjs "원본-Qcells-635-640.pdf"
```

## 양면 전용 등록 제한 (v3)

새 등록만 제한하며, 기존 현대·통웨이 등 등록 데이터는 수정하거나 비활성화하지 않습니다.
모델을 바꾸면 양면 유형 선택·근거 페이지·근거 문구·검토 체크를 초기화합니다.

- 단면 값 복사 버튼을 제거했습니다.
- 관리자에게 양면 제품 확인 상태, 업로드한 PDF의 근거 페이지, 확인 문구를 받습니다.
- 페이지 번호는 서버가 분석한 실제 PDF 페이지 범위 내의 정수여야 합니다.
- STC·BNPI, 온도계수, 퓨즈 등 필수 수치를 모두 검증합니다.
- 후면 일사 13.5%의 양면 사양에서 출력·전류가 STC와 같거나 더 작으면 차단합니다.
- NOCT/NMOT/다른 발전 증가율은 BNPI를 대신할 수 없습니다.
- 근거는 관리자 확인 기록이며 자동 진위 판정이 아닙니다. 실제 원본과 대조하세요.

등록 API는 아래 코드를 HTTP 422와 함께 반환합니다. 브라우저 버튼을 우회해도 동일합니다.

| 코드 | 화면 사유 |
| --- | --- |
| MONOFACIAL | 단면 제품 |
| BIFACIAL_UNCONFIRMED | 양면 여부 미확인 (근거 누락·유효하지 않은 페이지 포함) |
| BIFACIAL_SPECS_MISSING | 양면 사양 부족 (필수 값 누락·범위·관계 오류 포함) |

확인 기록(status, page, text, rearIrradiancePercent)은 영속 카탈로그의 evidence에
원본 PDF 정보와 함께 보관합니다. 공개 계산기 카탈로그에는 이 관리자 기록을 노출하지 않습니다.

## 발전 증가율 10% 대체 사용 (v4)

v3의 ‘실제 BNPI가 없으면 무조건 차단’에 다음 명시적 예외를 추가했습니다.

1. 제품 유형과 PDF 페이지·근거는 이전처럼 필수입니다. 단면 제품은 계속 등록 불가입니다.
2. 기본 적용 기준은 실제 BNPI입니다. 기존 등록 데이터는 기존 계산을 유지합니다.
3. 실제 BNPI가 없고 제조사 표에 발전 증가율 10%의 출력·Voc·Vmp·Isc·Imp가 있으면
   ‘대체 사양 — 제조사 발전 증가율 10% 표’를 선택할 수 있습니다.
4. 명시적 대체 동의와 최종 검토가 필요합니다. 동의하지 않은 API 요청도 차단합니다.
5. 제조사 10% 표의 원본 수치를 그대로 사용하며 출력 비율은 STC의 약 1.10인지 검증합니다.
6. rearSpecMode=gain10으로 구분해 영속 저장합니다. evidence의 후면 일사량은 null이며
   발전 증가율 10을 기록합니다. 내부 bnpi* 키는 호환용 저장 칸이고 실제 BNPI라는 뜻이 아닙니다.
7. 계산은 고정 10% 시나리오입니다. 후면 일사율 입력을 비활성화하고 해당 입력과 관계없이
   대체 사양을 사용합니다. 10%를 후면 일사율 13.5%로 환산하거나 보간하지 않습니다.
8. 온도·Voc 여유·전류 계수는 기존 설계 모드대로 적용합니다. 자료 재현 모드의 저온 Voc는
   기존 정책대로 STC를 사용합니다. AC/DC 및 모듈 수 기준 용량도 STC입니다.
9. 계산 결과·검증 설명·견적 연결에 대체 조건을 표시합니다. 이는 예비 검토용 시나리오이며
   현장 발전량이나 최종 전기 설계 검증을 보장하지 않습니다.

Canadian Solar F67 630~660W 영문판의 `ELECTRICAL DATA | STC` 제목,
전체 모델명, 줄바꿈된 10% 행도 지원합니다. 7개 모델을 실제 원본으로 검증했습니다.
텍스트가 깨지는 한글판이나 이미지 PDF는 OCR 없이 복원하지 않습니다.

추가 검증:

```sh
node test/module-substitute-ui.cjs "Canadian-F67-630-660-EN.pdf"
```

## 등록 조건 선택 제거 및 무응답 개선 (v5)

이 절은 이전 수동 확인·동의 절차를 대체합니다.

- 모델 선택만 남깁니다. 제품 유형·적용 기준·대체 동의·검토 체크 및 근거 입력을 제거했습니다.
- 실제 BNPI가 있으면 우선 사용하고, 없으면 확인된 제조사 10% 표를 자동 적용합니다.
- 적용 기준은 읽기 전용 설명으로 표시하고, 등록 불가 사유는 버튼 바로 아래에 표시합니다.
- 서버는 업로드된 PDF의 분석 결과와 modelId로 판정합니다. 클라이언트의 임의 제품 유형·동의·기준 값은 판정에 사용하지 않습니다.
- 실제 근거 페이지와 적용 기준을 서버가 생성해 카탈로그에 기록합니다. 등록 클릭은 추출 내용을 확인한 뒤 실행하세요.
- 양면 근거/필수 사양을 확인할 수 없는 미지원 표나 이미지 PDF는 수동 동의로 통과시킬 수 없습니다.
- 양면 적용값은 원본 모델 데이터에서 채우고 화면에서는 읽기 전용입니다.
- 기본 정보·STC·온도·보호 사양은 확인·보완할 수 있지만 서버의 수치 검증은 유지됩니다.
- 비활성 버튼은 금지 커서로 표시합니다. 실제 작업 중에만 진행 커서를 표시합니다.
- 등록 요청은 20초, PDF 분석 요청은 90초 대기 후 오류를 표시하고 처리 상태를 해제합니다.
- 시간 초과는 서버 등록 실패를 확정하는 것이 아닙니다. 재등록 전에 목록을 확인하세요.

적용 시 private HTML, 등록 JS/CSS, PDF 분석기와 server/modules.js를 함께 교체해야 합니다.
서버를 재시작하고 Ctrl+F5로 새로고침하세요. 버전이 섞이면 등록 요청이 거절될 수 있습니다.
